# io-v2.0: I/O card v1.1 + the CompactFlash interface (placement options, NOT routed)

2026-09-23. The backplane has only eight slots, so the CF interface (the standalone CF card v1.0,
[`../../../cf/kicad/v1.0`](../../../cf/kicad/v1.0/)) moves onto the I/O card. This folder has the v2.0 schematic, a
netlist proof, and **three placement options** for Ken to review before anything is routed.

`MASTER` marks this folder as hand-maintained, so `tools/eagle_to_kicad_all.py` never writes to it. Everything here is
generated by `build.sh` from `io_v2_netlist.py` (the circuit delta), `placements.py` (the options) and `../v1.1` (the
unchanged v1.1 design).

## What changed from v1.1

- **Circuit:** v1.1 is unchanged, pin for pin. The CF section is added: the CF card v1.0 circuit **minus** its 74LS138
  (U1), bus connector (X1), U1's capacitor, PWR LED (the card already has PWR0 + R2) and DASP LED (Ken). v1.1 **has** a
  power LED, so the CF card's PWR LED was not carried over.
- **Ports:** the CF decode now comes from the I/O card's own **IC5 (74LS138)**. **Y4 (pin 11, -IO-SEL4) = P4** is the
  register-select latch (write: bits 0-2 = ATA register DA0-2, bit 3 = CF reset). **Y5 (pin 10, -IO-SEL5) = P5** is the
  data port (read/write). They replace the CF card's -P8SEL / -P9SEL.
  - On v1.1, Y4 and Y5 connected only to the IO-ADDR and DATA-ADDR jumper headers (pins 8 and 6). They had no
    consumer on the card, so they were not literally unconnected. `check_netlist.py` prints and verifies this.
  - **The IO-ADDR-HL strap must be in P0-P7** (jumpers 3-5 and 4-6, the "L" end).
  - **The IO-ADDR / DATA-ADDR jumpers must never select P4 or P5.**
  - Both rules are in the silkscreen text and in notes on schematic sheets 5 and 7.
- **Schematic:** sheets 1-6 are v1.1's, copied, with two edits on sheet 5:
  - the four -IO-SEL4 / -IO-SEL5 labels became boxed global labels (only global labels cross sheets);
  - a strap note was added.

  Sheet 7 is the CF section. It is drawn by the CF card's own sheet writer (`gen_cf.py`, class `Sheet`, reused
  read-only) in the same style: stubs to labels, and global labels for the shared nets DATA0-7, -IO-RD, -IO-WR,
  -RESET, -IO-SEL4 and -IO-SEL5.
- **Board:** the same outline (177.83 x 114.02 mm) and X1 position as v1.1, because it starts from the v1.1 board file,
  so it fits the same backplane. The v1.1 footprints and their copper are kept. v1.1 copper that a move or a new part
  broke is removed (see below). The board title silk reads "YACC1 IO V2.0".

### Part-list delta (v2.0 minus v1.1)

The parts added are:

- 74LS32, 74LS175, 74LS08, 74LS245
- shrouded 2x20 IDC header
- 1x4 and 1x2 pin headers
- 10k x8 SIP9 network
- 4x 10k, 1x 1k (0207, 10.16 mm pitch)
- one 5 mm LED (ACT)
- 4x 100 nF disc capacitors, 1x 10 uF radial capacitor

Everything is through-hole. Nothing is removed from v1.1. The BOM is `io-v2.0-bom.csv` (kicad-cli, grouped by value
+ footprint). `tools/gen_bom.py` reads only Eagle schematics, so it cannot make this one.

## Proof and checks (build of 2026-09-23)

- **Netlist proof: MATCH** (`reports/netlist-proof.txt`, `check_netlist.py`).
  - The v2.0 schematic netlist equals the v1.1 schematic netlist (exported fresh from `../v1.1`) plus the CF section:
    - 71 + 19 = 90 parts;
    - 195 nets;
    - 62 CF pins joined onto 15 shared nets;
    - 42 unconnected pins = v1.1's 25 + the CF card's 17 documented no-connects.
  - v1.1's nets keep their names, except that -IO-SEL4/5 became global. Every CF pin is accounted for.
  - Every dropped CF X1 bus pin is on the same-named net of the I/O card's X1.
  - Each option board's pads carry exactly the schematic nets, with the same names.
  - Negative tests all report MISMATCH: a wrong CF pin, a wrong IC5 pin, and a swapped pad on a board.
- **ERC:** 131 = v1.1's 130 (the Eagle-conversion residue, identical) + 1 designed-in item: `isolated_pin_label`
  on SRST, the CF card's one-pin probe net. There are **0 new errors** (`reports/erc-summary.txt`).
- **DRC (each option, with schematic parity):** no copper violations beyond what v1.1 itself has.
  - Parity: 67 items, all inherited. The v1.1 board keeps the Eagle board values (for example "74LS00N" where the
    converted symbol says "74\*00") and 4 "Eagle name" fields. v1.1 run beside its own schematic has the same items
    plus 199 net-name conflicts, which v2.0 no longer has.
  - Silk overlaps rise from 60 to 70-102. These are the new parts' reference texts; tidy them after the choice.
- **Placement check** (`gen_io_v2.py check`, all options OK):
  - no new body overlaps (courtyards of the KiCad footprints, pads plus silk of v1.1's Eagle footprints);
  - every pad of a moved or new part is at least 0.5 mm from the edge and outside the LCD keepout.
- **Area:** the CF parts' courtyards total about 1,860 mm² (the IDE header alone 595 mm²). That is about 9% of the
  board. It fits, but only by using the gaps: no contiguous free block that size exists on v1.1.

## The options

Each option has:

- `io-v2.0-option-<x>.kicad_pcb` (+ `.kicad_pro`)
- `io-v2.0-option-<x>-render-top.png`: 3D render; the dashed adapter outline is shown on silk in the render only
- `io-v2.0-option-<x>-placement.png`: 2D plot of copper, silk, the adapter outline and the ratsnest

The CF-to-IDE adapter (about 60 x 43 mm, standoffs to be decided) is drawn dashed on **User.Drawings**.

Orientation: in the machine the card stands on X1. Board +x ("up" on the card) runs from the logic to the switch row,
then the LCD, then the LED row. The IDE header "band" is the strip between the logic and the switch row.

| | A | B | C |
|---|---|---|---|
| IDE header J2 | vertical in the band, beside the switch row | along the top edge (board y = 10), pin 1 at the switch end | vertical in the band |
| CF chips | IC12/IC14/IC15 in a row along the top edge; IC13 in the band under J2 | all four in one column in the band | spread: IC15 in the band, IC13 bottom-left by X1, IC12/IC14 under the LCD above the DB9 |
| v1.1 parts moved | switch row + IN + INPUT up 3.8 mm; IC3, IC10 (+C15, C16) down 2.54 mm | same as A | **no IC or switch**: the MAX232 caps C1-C4 (into a 2x2 block below the header), IC1's cap C7 (to the VCC end of IC1) and JP1 (up 7.3 mm) |
| adapter over | the upper-right logic (IC1, IC2, IC10...), connector edge facing J2 | the upper logic (IC1, IC3, IC10), connector edge over J2 | the upper-right logic, like A |
| v1.1 copper kept | 973 of 1567 | 900 of 1567 | **1030 of 1567** |
| ratsnest | 198 (117 CF, 81 broken v1.1) | 205 (114 CF, 91 v1.1) | **172** (106 CF, 66 v1.1) |
| comfort | fits; the band and top strip are full, with 0.2-0.6 mm between courtyards | fits; the tidiest CF block and the shortest glue wiring, but the column is tight against the switches | fits, and the most v1.1 stays; the CF glue runs across the whole board (longest routing) |

"v1.1 copper kept" counts the v1.1 track segments and vias that are left. v1.1 copper that ended on a moved pad was
dropped. Copper that a new or moved part made collide or dangle was then trimmed by DRC passes, eaten back to the next
junction.

Most of the loss in A and B is the switch row: each toggle's traces run to IC3 and the rails. The top strip and the band
under J2 were routing channels on v1.1, so every option loses some copper there. C keeps the switch copper, but it
costs the long CF runs.

Common to all options:

- ACT LED + R15 sit in the LED column between OUT and PWR (silk "ACT").
- Silk texts: "HL STRAP: P0-P7 ONLY (CF on P4/P5)" above IO-ADDR-HL, and "NOT P4/P5" beside both the IO-ADDR and the
  DATA-ADDR headers.

## Open questions for Ken

1. **Pick an option** (or a mix). Routing comes after that. Freerouting plus `tools/kicad/kicad_route.py`, as on the
   CF card, would have to route around the kept v1.1 copper.
2. **Adapter mounting:** standoff hole positions and heights are left until you measure the SinLoon adapter. No holes
   are placed yet.
   - Which side of the adapter is its male IDE header on, and does it point sideways or down? This sets which way J2's
     key and pin 1 should face, and how long the ribbon is.
   - Do the standoffs clear the DIP sockets and the J2 shroud plus the IDC plug (about 15 mm)?
   - Does the stack still clear the neighbouring slot? The slot pitch is not in the tree.
3. **Adapter power:** is J3 (+5 / GND / GND / n.c., 0.1") right for the adapter's power input (floppy Berg?)? Fit JP2
   (+5 V on IDE pin 20) only if it takes power there.
4. **Switch move (A, B):** is a 3.8 mm shift toward the LCD acceptable mechanically? The switch bodies end about
   0.6 mm from the LCD module's outline. C avoids this move.
5. The four MAX232 charge-pump caps move about 20 mm away from IC2 in C (fine electrically at MAX232 frequencies).
   C7 moves to IC1's VCC end, which is arguably better.
6. Standing (2.54 mm pitch) resistors or a second SIP network for R11-R14 would free space. That was not done, because
   the parts stay exactly those of the CF card v1.0.

## Rebuild

    hardware/cards/io/kicad/v2.0/build.sh             # ~2 minutes; OPTIONS="a" for one option

1. `gen_io_v2.py sch`: copy the v1.1 sheets and libraries; write sheet 7 and the project.
2. ERC gate.
3. Per option, run `gen_io_v2.py board | trim | check | review`, then DRC with schematic parity (in a temp copy
   beside the schematic) and the images.
4. `check_netlist.py` proof.
5. Schematic PDF (`io-v2.0-schematic.pdf`) and BOM.

The steps need:

- KiCad 10 (kicad-cli and its Python);
- Inkscape (SVG to PNG for the placement plot).

Board UUIDs of new items are not reproducible run to run. Everything else is deterministic.

To change the circuit, edit `io_v2_netlist.py`. To change a placement, edit `placements.py`. Then re-run `build.sh`.
Once an option is chosen and hand-edited in pcbnew, stop regenerating that board. Rename it to `io-v2.0.kicad_pcb`
so that the schematic project owns it, and keep `check_netlist.py` as the proof.
